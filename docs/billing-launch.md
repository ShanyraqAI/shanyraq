# Freedom Pay: запуск оплаты Shanyraq AI

Интеграция выключена по умолчанию. Без доступа мерчанта реальные платежи,
ограничения и письма не включать. Существующие организации до даты запуска
сохраняют доступ; для перевода таких клиентов нужен отдельный согласованный переход.

## Настройка

1. Получить Merchant ID и **секретный ключ приёма**, а не выплат, Freedom Pay Kazakhstan.
   Ключи хранить только в защищённых переменных Vercel, не в репозитории/чате.
2. Применить `prisma/migrations/20260831010000_billing/migration.sql` к нужной базе
   через Prisma и записать миграцию в историю. Не выполнять db push/reset поверх рабочей базы.
3. Настроить `APP_URL` (HTTPS origin), `FREEDOMPAY_MERCHANT_ID`,
   `FREEDOMPAY_SECRET_KEY`, `FREEDOMPAY_MODE=test`. `BILLING_ENABLED=false`.
4. Кабинет мерчанта: одноэтапное списание (`pg_postpone_payment=0`), без сохранения
   карт и рекуррентных списаний. Result URL: `/api/billing/freedompay/result`,
   Check URL: `/api/billing/freedompay/check`, оба POST. В подписях используются
   имена `result` и `check` без завершающего слеша.
5. Согласовать с Freedom Pay документы продавца, публичную оферту, возвраты,
   фискальные чеки и применимые налоговые реквизиты. Интеграция не генерирует
   фискальные чеки сама. До этого не включать live.
6. Email: `RESEND_API_KEY`, `EMAIL_FROM` с подтверждённым доменом и `CRON_SECRET`.
   Письма отправляются только владельцам с `User.emailVerifiedAt != null`.
   Незавершённая проверка email означает, что доступны только уведомления в кабинете.
   Ежедневная задача работает около 10:00 Казахстана. Напоминания — в окнах
   «до 3 суток», «до суток», «срок истёк». Точный срок доступа не зависит от cron.
7. После всех проверок: `FREEDOMPAY_MODE=live`, `BILLING_ENABLED=true`,
   `BILLING_START_AT=<фиксированная дата запуска в UTC ISO, с Z>`, затем deploy.
   Не менять дату запуска для перезапуска триалов. Отсчёт нового аккаунта идёт
   от создания организации, ровно 14 × 24 часа, даже если пользователь вошёл позже.

## Обязательные проверки в sandbox до live

- Успешная и отменённая оплата, отказ банка, возврат без Result URL.
- Фактические XML init-ответы и формы Check/Result соответствуют документированному
  протоколу. Парсер init принимает только плоские поля; неизвестная структура
  безопасно отклоняется. Проверить домен redirect_url в whitelist Freedom Pay.
- Result URL приходит с корректной подписью, amount/currency/testing_mode и
  `pg_captured=1` для банковских карт. Не подтверждать доступ по одной авторизации.
- Дубликаты/одновременные callbacks не продлевают доступ дважды. Подмена суммы,
  валюты, ID платежа, режима и подписи не меняет подписку.
- Возврат на success URL без callback не открывает доступ. Платёж другой
  организации не отображается. Тестовые платежи не продлевают live-подписку.
- Сбой сервера, повторные уведомления Freedom Pay. При пропущенном подтверждении
  дольше окна повторов использовать «Проверить оплату»: сервер запрашивает
  get_status3.php и проверяет подпись, сумму и валюту ответа. Вложенные сведения
  о возвратах требуют ручной сверки в кабинете Freedom Pay; не менять статус
  по скриншоту клиента. Незавершённый счёт блокирует создание второго до проверки.
- На границе trialEndsAt чтение остаётся, сервер отклоняет изменения. Синхронизация
  уже подключённых каналов и управление безопасностью аккаунта остаются доступны.
- Письма не дублируются при повторном запуске задачи и не отправляются после
  продления периода. Проверять результаты cron `failed`/`more` и ошибки доставки.

## Тарифы и продление

Start 9 900 ₸ / месяц (3 номера), Pro 19 900 ₸ (15), Business 39 900 ₸ (50).
Год — 10 месячных платежей. Цены взяты с текущего лендинга. Количество номеров
суммируется по организации. Период продлевается от более поздней даты:
текущее время, конец триала, конец оплаченного периода. Месяцы календарные,
даты конца месяца ограничиваются последним днём целевого месяца.
Во время оплаченного периода доступно продление того же тарифа; смена тарифа
с перерасчётом и автоматические возвраты в эту задачу не входят.
