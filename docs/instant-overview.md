## Архитектура этого изменения

- `OverviewWorkspace` находится в существующем dashboard layout, вокруг общей оболочки.
- Только подготовленный переход на **точный `/dashboard` без query/hash** перехватывается в capture-фазе. Модифицированные клики, новые окна и другие маршруты остаются штатными.
- Применяется документированный Native History API Next.js: URL/usePathname меняются без ожидания RSC. Outlet действительно показывает клиентский обзор, а не прежний экран под новым пунктом меню.
- Рендер обзора и его UI-состояние сохраняются между переходами. Скрыт только текущий server outlet; все разделы приложения в DOM не сохраняются. Сохранение других экранов пока не гарантируется.
- Обзор запрашивается четырьмя независимыми блоками: `core`, `attention`, `recent`, `channels`. Ошибка одного не очищает остальные. Основные показатели внутри core пока используют общий существующий getDashboardStats.
- Новые пользовательские записи, локальные брони, платежи или сообщения не создаются. Серверные операции и существующий outbox не заменены.
- В новом режиме строка последних броней открывает существующую подробную страницу, а не inline-редактор: полный справочник гостей/тарифов не скачивается ради обзора. В legacy-режиме прежний диалог сохранён и загружается лениво.
- Локаль учитывает cookie и сохранённый язык объекта; tenant helper дополнительно выбирает уже существующее поле language. Изменения схемы нет.

## Копии данных и хранение

| Набор | Что сохраняется | Ограничение |
| --- | --- | --- |
| core | Показатели текущего рабочего дня, агрегированные тренды/прогноз, минимальные строки заездов/выездов, подписи | Существующий расчёт статистики; нет базы всех гостей |
| attention | Депозиты, возможные конфликты, уборка/обслуживание; минимальные подписи и внутренние ссылки | До 12 сохранённых элементов; серверные выборки ограничены |
| recent | ID, номер брони, имя гостя, квартира, даты, канал, стоимость брони, статус | До 20 строк |
| channels | Минимальные статусы интеграций | Только при доступности продукта channels; секретов нет |

`shanyraq-read-snapshots` — отдельная IndexedDB, schema 1. Ключ: schema + user/org/hotel/role/resolved permissions + resource + рабочий день/локаль.
Запись содержит успешное время обновления, время старта запроса и content-hash ETag; это не версия транзакции PostgreSQL и не подтверждение актуальности доступности.
Лимиты: 256 KiB на снимок, 24 снимка / 4 MiB суммарно, TTL 7 дней. Эвикция/очистка относятся **только к read copies**.
При недоступной/переполненной IndexedDB остаётся память текущей сессии и видимое предупреждение. Offline readiness после перезапуска тогда не обещается.

Не сохраняются токены/пароли/sessionId, подписные URL, PDF, фотографии, платёжные реквизиты, методы оплаты, события депозитов/платежей, гостевые контакты/заметки или редакторские справочники. Стоимость брони и финансовые агрегаты сохраняются как явно помеченные read copies для нужного интерфейса.

## Синхронизация и безопасность

- Local hydration и сеть запускаются независимо: медленный запрос не мешает показу сохранённой копии.
- Один in-flight запрос на ресурс, timeout 15 s, до трёх повторов с exponential backoff и jitter. Отсутствие сети не создаёт бесконечный retry loop.
- Обновление при подготовке, открытии обзора, возврате на foreground, online, успешной поддерживаемой мутации и обновлении server children. Закрытое PWA не обязано выполнять фоновые задачи.
- Поздний local load не перезаписывает новый ответ. При смене контекста запросы отменяются, поздние ответы игнорируются. IndexedDB-транзакция не принимает запись от более старого запроса другой вкладки.
- Успешный пустой результат заменяет старый набор; ошибка сохраняет его. Неподготовленные блоки имеют отдельный честный статус, а не фиктивные нули.
- Каждый GET самостоятельно проверяет пользователя, организацию/объект, право OVERVIEW, право RESERVATIONS для recent, день, локаль и совпадение scope. Клиент не выбирает hotelId для SQL.
- Ответы private/no-store; пользовательский HTML/RSC/API не помещаются в Cache Storage.
- 401/403/смена контекста прекращают чтение, убирают частный экран и очищают соответствующий read scope. Logout/login entry очищают read copies; прежняя явная политика outbox при выходе сохранена.
- Storage event смены пользователя/объекта другой вкладкой немедленно закрывает старый экран. Изменение схемы read cache не затрагивает очередь и черновики.
- Нет сети — устройство не узнает мгновенно об отзыве прав/истечении сессии. Локальная копия не даёт прав на серверные операции. IndexedDB не является зашифрованным сейфом; устройство должно быть доверенным.

## Что ещё требует сети

Начальная авторизованная загрузка оболочки, неподготовленные разделы, подробная карточка брони, серверное подтверждение любых изменений, актуальная доступность/финансы, загрузка несуществующих в кэше данных. Поддерживаемый outbox может сохранить намерение, но это не подтверждённая бронь/оплата/доставка.

Холодное открытие установленного PWA **полностью без сети после закрытия** пока по-прежнему попадает в общий /offline. В этом PR нет безопасного офлайн-bootstrap identity/shell. Это обязательная оставшаяся работа, а не пройденная приёмка.

## Воспроизведение

В полном checkout:

```bash
npm run test:instant-overview
npx tsx --test src/lib/offline/dispatch.test.ts src/lib/offline/outbox.test.ts
npm run lint
npx tsc --noEmit
npm run test:reliability
npm run build
```

Полные последние четыре gate нужно выполнить в штатной среде, не обходя communications/schema/release проверки. Не подставлять production DB для локальных проверок.

Для изолированной production fixture без PostgreSQL (внешние test-only инструменты; Playwright не добавлен в зависимости приложения):

```bash
node scripts/create-instant-overview-fixture.mjs /tmp/shanyraq-overview-fixture
cd /tmp/shanyraq-overview-fixture
npm install --ignore-scripts
npx next build
npx next start -H 127.0.0.1 -p 3188
```

В отдельной тестовой среде, где уже установлен Playwright/Chromium:

```bash
INSTANT_OVERVIEW_TEST_URL=http://127.0.0.1:3188 node scripts/test-instant-overview-browser.mjs --fixture
node scripts/test-read-snapshots-browser.mjs
```

Опциональные пути инструментов: `PLAYWRIGHT_MODULE_PATH`, `CHROMIUM_PATH`; каталог отчётов/видео: `INSTANT_OVERVIEW_TEST_OUTPUT`. Production fixture использует только тестовые ID и данные.
Для Preview: убрать `--fixture`, передать авторизованный `INSTANT_OVERVIEW_STORAGE_STATE`, `INSTANT_OVERVIEW_TEST_LOCALE` и `ALLOW_PREVIEW_READ_TEST=true`. API в этом скрипте всё равно подменён; отдельно проверить живые API/права. Storage-state файл не коммитить.
