# Пакеты документов и SMS Mobizon

## Реализованный способ

Самостоятельная фиксация действий **owner-first**. Авторизованный OWNER явно подтверждает полномочия, прочтение всех PDF и передачу пакета. Гость отдельно принимает каждый обязательный пункт; необязательный PDF можно не принимать; инструкция заселения информационная. Маркетинговых согласий нет.

Это не ЭЦП, не независимая проверка личности и не утверждение о юридическом заключении договора. `legalStatus` всегда `NOT_LEGALLY_REVIEWED`. До реального использования договоров требуется проверка юристом Казахстана текста, способа идентификации, полномочий и хранения доказательств. Код не подставляет подпись владельца автоматически и не подписывает за людей.

Пакет хранит полный неизменяемый PDF, текст правил/депозита/отмены/инструкции, SHA-256, версию согласия, раздельные события сторон. JSON-архив содержит исходные PDF в base64 и журнал; это не криптографическая подпись архива и не независимый доверенный timestamp. Сервис не переписывает старые подтверждения. Администратор БД технически может изменить данные — для юридического архива нужна дополнительная утверждённая политика хранения.

Новая версия отзывает прежние ссылки, но сохраняет архив. Изменение брони, гостя/телефона, реквизитов, комнаты, коммуникационного профиля или правил делает прежний пакет неактуальным. Владелец сохраняет доступ к архиву даже после отмены брони. Ссылка: 256-битный секрет во fragment, срок 1–14 дней, отзыв. В таблице пакетов хранится только хеш секрета; подготовленное личное сообщение, естественно, содержит добавленную ссылку. Гостевая страница не сохраняет её в localStorage/history и использует существующие no-store/no-referrer/private CSP-заголовки `/guest/*`.

## Почему Mobizon.kz

Выбран местный API с документированным SendSmsMessage и тарифами для верификационных сообщений. Это практичный выбор для реализации, **не доказательство абсолютной минимальной полной стоимости**: цена зависит от операторов, категории сообщения, регистрации имени и объёма.

Официальные источники, проверенные 17.10.2026:
- https://mobizon.kz/prices — тариф 2, своё имя: базовый SMS Beeline 17,80 KZT, Kcell 16,60 KZT; у Altel/Tele2 категория верификации 10,40 KZT. Плата за имя соответственно 17 400 / 14 500 / 20 800 KZT в месяц. Для Beeline требуется тариф со своим именем; регистрация может занять до 30 дней. Применимость категории OTP нужно подтвердить у провайдера.
- https://smsc.kz/tariffs/ — альтернативный базовый тариф: Kcell 17,60 KZT, Beeline 19,70 KZT, Tele2/Altel транзакционные 12,10 KZT; полная сопоставимая стоимость имён и маршрутов не подтверждена.
- https://mobizon.kz/help/api-docs/message — официальный endpoint/параметры и идентификатор принятого сообщения. Принятие не является доставкой.

Перед покупкой владелец должен получить актуальный расчёт стоимости и условия для своих сетей. Код не регистрирует аккаунт, не пополняет баланс и не делает платных тестовых отправок автоматически.

## Подключение сервером

По умолчанию оба флага выключены:

```
GUEST_DOCUMENT_BUNDLES_ENABLED=false
DOCUMENT_SMS_ENABLED=false
```

После подключения владельцем аккаунта и регистрации своего sender администратор задаёт **только на сервере**:

```
MOBIZON_API_KEY=<секрет аккаунта>
MOBIZON_SENDER=<зарегистрированное имя, 1–11 разрешённых символов>
DOCUMENT_OTP_SECRET=<случайный отдельный секрет минимум 32 символа>
APP_URL=https://<домен Shanyraq>
```

Ключи не вводить в GitHub/чат, не использовать `NEXT_PUBLIC_*`. Секрет OTP стабилен между инстансами; его ротация отменяет незавершённые коды и меняет ключи лимитов — необходим отдельный план ротации. Наличие переменных означает «настроено», но не «проверена доставка».

Документированный Mobizon API передаёт `apiKey` в query серверного запроса. Адаптер не печатает URL, исключения fetch, тело/код или сообщения провайдера; отключите внешнее HTTP tracing/full-URL logging для этого endpoint. Redirect запрещён, URL жёстко задан. Нужен отдельный аккаунт/лимит для окружения Preview. Настройки сейчас общие для установки, не multi-account BYO для каждого клиента SaaS.

## OTP и стоимость

- 6 случайных цифр, TTL приложения 5 минут, одно использование, максимум 5 проверок.
- HMAC связывает код с challenge, точным хешем пакета, телефоном, действием и версией согласия. В БД нет открытого кода.
- Повтор: минимум 60 секунд; максимум 5 SMS на телефон и 50 на организацию за скользящие 24 часа. Номера только явного поддерживаемого списка мобильных префиксов Казахстана; 8-префикс не угадывается.
- Попытка платной отправки фиксируется **до** сетевого вызова. Уникальный requestKey повторно не отправляет SMS. Провайдер не документирует idempotency API, поэтому обещать exactly-once при сетевом сбое нельзя.
- `PENDING/UNKNOWN`: не считать ни доставкой, ни успешным подтверждением. Автоматического повтора нет; новый явный запрос не ранее 10 минут. Падение между вызовом и записью результата оставляет PENDING. Это требует понятного восстановления, а не фоновой повторной тарификации.
- `ACCEPTED` означает только принятие провайдером. Проверка доставки и банковские/юридические статусы не подделываются.
- GET/view/download не принимают условия и не отправляют SMS. Код запрашивается только отдельным действием гостя; подписка владельца должна разрешать запись.

## Выпуск

1. Проверить `20261017160000_document_agreements/migration.sql` и применить к **отдельной Preview DB** штатным reviewed-release процессом. Никаких production-миграций из Preview.
2. Prisma generate, lint, полный build/CI в полном checkout; затем включить `GUEST_DOCUMENT_BUNDLES_ENABLED` в Preview. Read-only schema gate проверяет четыре новые таблицы только при включённом флаге.
3. Проверить реальный вход OWNER, создание PDF, пакет, гость с отдельного устройства, отзыв, отмену и экспорт. Проверить существующие CSP/Clarity/SW именно на deployed guest page.
4. Только после настройки аккаунта отдельно разрешить и выполнить ограниченный платный тест SMS. Проверить баланс, sender, реальные операторы и двустороннюю доставку. Синтетические тесты этого не доказывают.
5. Юридический review и утверждение процедур — отдельный обязательный выпускной контроль.

Не завершено всем ТЗ: общедоступная явно опубликованная версия правил без персональных данных; объединение запроса Kaspi, фото и пакета в одном управляемом сообщении; полноценная проверка native share на iOS/Android; полный CI/Preview и production-активация. Существующая отдельная Kaspi-форма сохранена. Без этих проверок нельзя утверждать «всё ТЗ готово в production».
