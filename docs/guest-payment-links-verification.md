## Воспроизведение

```sh
npx tsx --test src/lib/guest-payments/policy.test.ts
RUN_GUEST_PAYMENT_DB_TESTS=1 TEST_GUEST_PAYMENT_DATABASE_URL='postgresql://…@127.0.0.1:PORT/fixture' npx tsx scripts/test-guest-payments.ts
```

DB-скрипт намеренно разрешает только loopback URL с `fixture` в имени БД, отдельное явное opt-in и уже применённую reviewed schema. Он не сбрасывает БД, не применяет миграции автоматически и не должен запускаться против реальных данных.

## Не пройдено / ограничения

- Полная локальная `npm run build` запускалась: generate и schema gate прошли; Next/Turbopack завершился с 69 module-resolution errors из-за неполного локального экспорта репозитория (например, guards, account-form, config/freedompay, соседние dialog-компоненты). Это НЕ успешная сборка и не доказательство поломки этих файлов в полном GitHub-репозитории.
- Общий tsc также не зелёный в неполном экспорте (116 строк диагностик на момент проверки); в новых payment-модулях не осталось диагностик, но это не заменяет полный typecheck/CI.
- Проверки GitHub CI ранее недоступны текущему подключению (403); новый зелёный статус не заявлен. Vercel needs_reauth, Preview и production не проверены/не развёрнуты этим этапом.
- Не проверены реальная ссылка конкретного получателя, реальный Kaspi-платёж, нативное share на iOS/Android, SMS или юридический провайдер. URL allowlist приложения уже, чем потенциальные форматы банка.

Релизное решение: код можно интегрировать с выключенным флагом, но включение и production-ready статус запрещены до полного CI/build, reviewed migration и Preview. Незавершённые SMS/OTP и двусторонние комплекты явно перечислены в соседней инструкции.
